# 配置库的规划

# 配置库组成及其相关权限

配置库可分为源代码库、文件库、和程序库，开发工具库进行管理。

源代码库分为以下几类：

Dev分支：开发人员使用，不做管控。

Test分支：开发人员提交待测试的源代码，并由配置管理员进行合并，并建立的分支。配置管理员检出给测试人员进行测试；

Master分支：软件产品正式发布后，所有代码合并到Master分支。后续软件变更需从Master分支检出代码进行开发。

注：特殊情况下，其他人员需要申请相关库权限时，需提交申请，经批准后方可进行相应权限的行为。

文件库为所有已审核批准的文件。新建和变更文件参见《文件控制程序》。

程序库分为受控库和产品库。其中受控库用于存放提交测试的程序包和镜像包等；产品库用于存放正式发布的程序包和镜像包。

# 软件配置变更控制

# 软件配置变更流程

按《变更控制程序》文件发起变更申请；

当变更申请通过后，从Master分支检出配置项至Dev分支，供软件工程师进行开发；

软件工程师执行变更；

进行变更确认（测试）；

审核变更；

结束变更；

7 配置库的规划

7.1 配置库组成及其相关权限

配置库可分为源代码库、文件库、和程序库，开发工具库进行管理。

源代码库分为以下几类：

7.1.1 Dev 分支：开发人员使用，不做管控。

7.1.2 Test 分支：开发人员提交待测试的源代码，并由配置管理员进行合并，并建立的分支。配置管理员检出给测试人员进行测试；

7.1.3 Master 分支：软件产品正式发布后，所有代码合并到 master 分支。后续软件变更需从 Master 分支检出代码进行开发。

注：特殊情况下，其他人员需要申请相关库权限时，需提交申请，经批准后方可进行相应权限的行为。

文件库为所有已审核批准的文件。新建和变更文件参见《文件控制程序》。

程序库分为受控库和产品库。其中受控库用于存放提交测试的程序包和镜像包等；产品库用于存放正式发布的程序包和镜像包。

8 软件配置变更控制

8.1 软件配置变更流程

8.1.1 变更发起人填写《变更控制审批表》，包含变更具体内容和变更理由；

8.1.2 提交变更申请，召集相关部门进行评审；

8.1.3 审核变更申请

8.1.4 分配任务至软件工程师；

8.1.5 当变更申请通过后，从 Master 分支检出配置项至 Dev 分支，供软件工程师进行开发；

8.1.6 软件工程师执行变更；

8.1.7 进行变更确认（测试）;

8.1.8 审核变更；

8.1.9 结束变更；
