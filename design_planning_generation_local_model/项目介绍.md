# 设计策划文档生成系统 v2.0 项目介绍

## 1. 项目概述

**设计策划文档生成系统**是一个面向医疗器械企业的 AI 驱动质量体系文档生成平台。系统基于大语言模型（LLM），结合 RAG（检索增强生成）、多代理协作（Multi-Agent）和本地化部署，能够通过自然语言对话引导用户完成医疗器械全生命周期文档的策划、编写、审阅与下载。

项目聚焦于**贴敷式胰岛素泵（Patch Insulin Pump）**这一 III 类有源医疗器械，覆盖其设计开发全过程，输出符合 ISO 13485、ISO 14971、IEC 62304、IEC 62366、GB 9706 等国际/国家法规标准的专业质量体系文档（Word .docx 格式）。

### 1.1 核心价值

- **降本增效**：将质量体系文档编写从数天缩短至数小时，通过对话式引导大幅降低编写门槛
- **合规保障**：内置法规标准知识库 + 163 种文档类型模板，自动对齐适用标准条款
- **专业质量**：多代理协作（框架设计师 + 章节编写师 + 摘要师），生成内容达到注册申报级别
- **本地化可控**：支持本地 Ollama LLM + 本地 MinerU 视觉解析模型，数据不出企业
- **人机协同**：HITL（Human-in-the-Loop）机制，关键章节生成支持用户确认/修改/拒绝

### 1.2 支持的文档类型（163 种，覆盖 9 大生命周期阶段）

| 阶段 | 文档数量 | 代表性文档 |
|------|----------|-----------|
| 一、设计策划 | 14 | 设计开发策划书、产品需求规格书(PRS)、风险管理计划、软件开发计划、可用性工程计划、注册策略文件等 |
| 二、设计输入 | 18 | 设计输入文件、软件需求规格书(SRS)、硬件/用户界面/网络安全需求规格书、用户需求规格书、初步风险分析、需求追溯矩阵(RTM)等 |
| 三、设计输出 | 24 | 产品图纸、BOM、产品规格书、软件架构/详细设计、硬件/固件设计、说明书(IFU)、工艺流程图、合格供应商清单等 |
| 四、设计验证 | 35 | 设计验证总计划、电气安全/EMC/输注精度测试报告、软件单元/集成/系统测试报告、生物相容性试验、包装运输验证等 |
| 五、设计确认 | 16 | 设计确认总计划、总结性可用性报告、临床评价报告(CER)、生物学评价报告、过程确认(IQ/OQ/PQ)等 |
| 六、设计转化 | 6 | 设计转化计划/报告、工艺验证计划/报告、灭菌确认方案/报告等 |
| 七、生产制造 | 14 | 批生产记录(BPR)、批检验记录、器械历史记录(DHR)、DMR、生产/检验SOP、校准记录、UDI赋码记录等 |
| 八、注册申报 | 12 | 产品注册申报资料、产品技术要求、风险管理报告、符合性声明(DoC)、网络安全披露文档、QMS证明文件等 |

### 4.3 ★ Agent 引擎（app/services/agent_engine.py，27KB）

系统的**核心模块（v2.0）**，基于 LangGraph StateGraph 构建 ReAct Agent 循环：

**核心架构**：
- **StateGraph**：定义 Agent 状态机（`_agent_node` → `tools_condition` → `ToolNode` / END）
- **ReAct 循环**：LLM 自主决定调用工具或直接回复
- **HITL 暂停**：`generate_section` 工具通过 `interrupt()` 暂停，等待用户确认
- **检查点持久化**：`AsyncSqliteSaver` 自动保存状态到 `project_store/agent_checkpoints.db`
- **SSE 流式输出**：`astream_events()` 实时推送 token、工具调用、工具结果
- **自动模式**：`auto_mode=True` 时跳过所有 HITL 确认

**Graph 节点**：
1. `_agent_node`：LLM 决策 + 生成回复（含上下文压缩、状态同步）
2. `_pre_tool_node`：工具执行前检查（对 `generate_section` 触发 HITL interrupt）
3. `ToolNode`：执行工具调用

**模型配置**：
- 通过 `ChatOpenAI` 兼容接口调用本地 Ollama
- 默认模型：`qwen3.5:122b`（128K 上下文）
- `temperature=0.3`，`max_tokens=4096`

### 4.4 ★ Agent 状态管理（app/services/agent_state.py）

多代理协作架构的核心组件，每个子代理拥有独立 LLM 实例和上下文：

opt-in 的本地视觉文档解析服务：

- **启用方式**：环境变量 `USE_MINERU=true`
- **支持格式**：PDF / DOCX / DOC / PPTX / XLSX / PNG / JPG / BMP / TIFF / WebP
- **子进程隔离**：在独立子进程中执行，避免 torch/transformers 与主服务冲突
- **回退机制**：未启用时自动回退到 python-docx / pdfplumber / tesseract

### 4.9 RAG 检索引擎（app/services/rag/）

#### 4.9.1 向量存储（vector_store.py，26KB）

#### 4.9.2 ★ 中文分词器（tokenizer.py）

#### 4.9.4 文档摄入（ingest.py，26KB）

│                                                         │

## 7. 关键设计决策

### 7.1 ★ 多代理协作架构
- 主 Agent 负责对话编排和工具调度
- outline_agent / chapter_agent / summary_agent 各司其职
- 子代理独立 LLM 实例，避免上下文污染
- 通过 `create_agent()` 创建，主 Agent 通过工具包装调用

### 7.2 ★ HITL（人机协同）
- `generate_section` 工具通过 LangGraph `interrupt()` 暂停执行
- 用户可确认/修改/拒绝每个章节
- `auto_mode=True` 时跳过所有 HITL，一键生成
- 状态持久化支持中断后恢复

### 7.3 ★ 状态持久化
- `AsyncSqliteSaver` 自动检查点（`project_store/agent_checkpoints.db`）
- 每轮对话后自动保存状态
- 支持进程重启后恢复对话
- 状态快照与 PRD Section 4.3 一一对应

### 7.4 ★ 本地化部署
- LLM：Ollama (qwen3.5:122b)，OpenAI 兼容接口
- 文档解析：MinerU2.5-Pro 本地视觉模型（opt-in）
- 向量库：ChromaDB 本地持久化
- 数据不出企业（除可选的 Web 搜索）

### 7.5 ★ 上下文压缩
- 滑动窗口 + 摘要压缩
- 85% 阈值触发，保留最近 15 轮完整对话
- 摘要保留关键决策和进度，不丢失重要信息

### 7.6 多层搜索策略
- **RAG（知识库）** → **附件检索** → **Web 搜索** 三层递进
- RAG：向量 + BM25 + Reranker 混合检索
- Web 搜索：Playwright（Agent 模式）/ Agent SDK（旧版表单）

### 7.7 分章节生成
- 文档拆分为多章节独立生成
- 每章专属检索查询和 Prompt
- 避免单次 token 超限，提高针对性

### 7.8 延迟初始化
- RAG / Web 搜索 / Agent 组件均延迟初始化
- 不可用时静默降级，不影响核心功能
